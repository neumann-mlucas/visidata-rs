visidata-rs · user guide

Explore tables in your terminal.

vdrs (visidata-rs) is a modal terminal data explorer. It reads CSV, Parquet, JSON, Excel and SQLite through Polars, shows them in a keyboard-driven table, and lets you sort, filter, pivot, join and query without leaving the terminal. If you know VisiData, most keys will feel familiar.

Install

You need a Rust toolchain (1.88 or newer):

cargo install --git https://github.com/neumann-mlucas/visidata-rs --locked

This installs the vdrs binary. --locked builds with the dependency versions the project is tested with; without it Cargo may pick newer, incompatible releases.

Opening data

vdrs sales.parquet                 # open in the TUI
vdrs data/                         # every *.parquet file in a directory, as one table
cat events.jsonl | vdrs -          # read stdin; format is sniffed
vdrs --format tsv export.txt       # force a format when the extension is wrong
vdrs --headless --head 20 big.csv  # print schema and the first 20 rows, no TUI
FormatExtensionsNotes
CSV / TSV.csv, .tsv, .tabFirst row is the header. ISO dates load as dates; other layouts (7/3/2018 is ambiguous) stay text until @. Column types come from the whole file (first 100,000 rows above 256 MB). Rows with too few fields are padded, extra fields dropped; invalid UTF-8 is replaced.
Parquet.parquet, .pq, a directoryA directory means all its *.parquet files.
Arrow IPC.arrow, .ipc, .feather
JSON Lines.jsonl, .ndjsonOne record per line.
JSON.jsonAn array of records. A .json file that is really JSON Lines is detected.
Excel / ODS.xlsx, .xls, .xlsm, .xlsb, .odsCells load as text; use the type keys to convert. Several worksheets → a list to pick from; book.xlsx:Sheet2 opens one directly (also in :join/:diff).
SQLite.sqlite, .sqlite3, .dbColumns load as text. Several tables → a list to pick from; app.db:users opens one directly.
gzipany of the above + .gzThe inner extension (or --format) decides the format.

Files are scanned lazily: vdrs only loads a 1024-row window around the cursor and counts rows in the background, so large files open immediately. Other formats can be added with a Lua loader.

A first session

Say sales.csv has columns date, region, qty and price. A typical look around:

  1. vdrs sales.csv. The table opens at once; the row count in the title bar shows ? until it has been counted.
  2. Move to region with l and press F: each region with its row count and percentage. Put the cursor on north and press Enter to see just those rows. q takes you back, one sheet at a time.
  3. On price, press ] to sort by it, most expensive first. On region, z| ^n Enter keeps the regions starting with n.
  4. Type :derive total = qty * price to add a column, then :pivot region date total: while you type, the right half of the screen tells you what comes next and previews the result.
  5. Press U if a step went wrong. When the view is what you want, :save north.parquet writes it, and :export north.py writes a Python script that rebuilds it from sales.csv.

Nothing you do changes sales.csv.

  • Title bar: the sheet name; chips for what shapes the view (a spinner while work runs, source format, open sheets, filter, sort with ▲/▼, sel count, hidden columns); then the current column with its position, and row N/total · % (? while rows are still being counted). Long names are shortened from the left so the position stays visible.
  • Header: column names with a dim type badge (i integer, f float, str text, date, …). On a sorted column the badge becomes ▲ or ▼, followed by its rank when sorting by several columns (▼2). Numbers and their headers sit on the right.
  • Status line: a short key hint, or messages, prompts (/, :, …), working: … while a long command runs in the background, a pending count (count: 3) or a pending key chord. When you press the first key of a chord (for example g or z), a popup lists what can follow.

Messages stay until your next key press.

Columns & types

KeysAction
-, g-Hide the current column; show all hidden columns.
!, z!Toggle the current column as a key column (moved to the left; used by W and D); clear all keys.
^Rename the current column.
zs, zcFreeze columns up to the cursor at the left edge; unfreeze.
# % ~ @Treat the column as integer, float, text, date. Values that don't convert show as · (empty).
:type currencyStrip everything but digits, . and - (so $1,200.50 → 1200.5) and make it a float.

The date conversion (@) understands 2024-01-31, 2024/01/31, 1/31/2024, 1/31/24, 31.01.2024, 20240131, 31 Jan 2024, Jan 31 2024, Jan 31, 2024 and January 31, 2024, and ignores a trailing time (7/3/2018 1:47p). Slash dates are read month first.

Search, sort, filter

KeysAction
/ then text, n, NFind text (case-insensitive) in any column of the whole sheet; next / previous match, wrapping around.
[, ], zoSort ascending / descending by the current column. Pressing it on more columns sorts by several. Clear sorting.
z| then a regex, zfKeep only rows whose current column matches the regular expression (works on numbers and dates too, by their text); remove the filter.

The same from the command line: :sort -price, :filter region ^n, :unsort, :unfilter. Column names with spaces need quotes: :filter "unit price" ^1\d+$.

Selecting rows

KeysAction
s or t, uToggle selection of the current row; unselect it.
gs, guSelect every row of the sheet (respecting the filter); clear the selection.
| then a regexAdd rows whose current column matches.
,Add rows whose current column equals the value under the cursor.
"Open a new sheet with just the selected rows.
:select-col-duplicatesAdd rows whose current column repeats a value from a row above.
:dedupe-rowsOpen a new sheet keeping the first row of each key (of each distinct row when there are no key columns).

Selections stick to rows, not positions: sorting or filtering keeps the same rows selected.

Sheets

Many commands open a new sheet on top of the current one. q closes the top sheet (and quits on the last one); S lists open sheets (Enter jumps to one). New sheets are built from what you see: the current filter, sort, types and visible columns.

Keys / commandOpens
FFrequency table of the current column: each value with count, percent and a histogram bar, most common first. On it, Enter opens the original rows with that value; select several values and press gEnter to open the rows of all of them.
IDescribe: one row per column with type, count, nulls, distinct, min, max, mean, median.
WPivot: one row per key-column combination, one column per value of the current column, counts in the cells. With no key columns: a single row of counts.
:pivot index on values [agg]Pivot with an aggregate: sum (default), mean, count, min, max, first, last, or a Lua aggregator. While you type it, a panel on the right says which argument comes next, lists the columns, and then previews the pivot of the first 10,000 rows; Enter pivots everything.
:unpivot a,b -- idLong format: columns a, b become variable/value rows, keeping id.
:join other.csv id [type]Join with a file, an open sheet's name, or #2 (sheet id from S) on columns with the same name. Types: inner (default), left, full, merge (full join; the other side's non-empty values win), append (stack rows, columns matched by name), concat (stack rows, columns matched by position, named after the current sheet's). Both need no key and add a hidden origin_sheet column naming each row's sheet; g- shows it.
D or :diff file [keys]Compare with another file. With key columns (D uses yours): the rows that differ, tagged only_a, only_b or changed. Without keys: a column-by-column schema comparison.
:sql SELECT … FROM selfRun SQL (Polars SQL) on the current sheet, called self. Other open sheets are s0, s1, … (ids from S).
g" or :dupA copy of the current sheet.

Commands that read the whole data (search, select all, |, ,, ", I, W, :pivot, :save) run in the background; the status line shows working: … and you can keep moving.

Changing data

vdrs never modifies your files; changes live in the sheet until you save.

CommandAction
:derive total = qty * priceAdd a computed column. The expression is SQL (CASE WHEN …, upper(name), price * 1.2, …).
:setcol 0Set the current column to a value on the selected rows. The value must fit the column's type.
:uniformHide columns that hold a single value.
U, RUndo, redo. Covers column changes, types, sorting, filtering, selection, :derive and :setcol (up to 100 steps per sheet).

Saving & export

CommandAction
:save out.parquet (:w)Write every row of the current view (filter, sort, types, visible columns). The extension picks the format: .csv, .tsv, .parquet, .arrow/.ipc, .jsonl, .json. An existing file is overwritten; an unknown extension is refused and leaves the file alone.
:export view.py, :export view.sqlWrite a script that rebuilds the current view from the source files: Python with Polars, or SQL for DuckDB. Derived sheets (frequency, copy, selected rows, :join, :sql, :pivot, W, :unpivot, describe, row diff) are rebuilt step by step from the sheet they came from, as it was when you made them.

For example, filtering region on ^n, pressing F on qty and running :export qty.py writes:

import polars as pl

t1 = pl.scan_csv("sales.csv")
t2 = t1.filter(pl.col("region").cast(pl.Utf8).str.contains("^n"))
t3 = t2.group_by("qty").agg(pl.len().alias("count")).with_columns(…).sort(["count", "qty"], …)

print(t3.collect())

Each sheet becomes one variable (t1, t2, …); in .sql each is a WITH table. Run it with python qty.py or duckdb -c ".read qty.sql". See Limitations for what can't be exported.

Following files

:tail app.jsonl -f opens a file that keeps growing and checks it every 2 seconds. With -f (follow), if you are on the last row you stay on the last row as new rows arrive. For CSV, TSV and JSON Lines only the new lines are read. :tail data/ -f on a directory picks up new Parquet files.

Plan panel

P opens a side panel with the Polars query behind the current window; press again for the optimized plan, a third time to close. Useful to see what a filter or join actually does.

Prompt editing

All prompts (/, :, filters, rename, diff) support: ← →, Home/Ctrl-a, End/Ctrl-e, Backspace, Del, Ctrl-u (delete to start), Ctrl-w (delete previous word). Enter runs, Esc cancels. In the : prompt, ↑/↓ walk the command history (kept in $XDG_STATE_HOME/vdrs/exline_history), and Tab completes the command name: one match is filled in, several are listed after the prompt and filled in up to where they differ.

Arguments are split on spaces; use quotes ("a b" or 'a b') or a backslash for spaces inside one argument.

Lua configuration

vdrs runs $XDG_CONFIG_HOME/vdrs/init.lua (usually ~/.config/vdrs/init.lua) at startup. The first time the TUI starts without one, vdrs writes it with every default binding listed but commented out: uncomment a line to change it. Defaults you leave commented keep following new releases. Saving the file while vdrs runs reloads it within about two seconds. If it has an error, everything registered before the error still applies and the error is shown in the status line.

-- ~/.config/vdrs/init.lua
vd.set_theme("light")                               -- "dark" (default) or "light"

vd.bind("sheet", "x", "goto_bottom", "jump to end") -- a key → an action
vd.bind("sheet", {"<Space>", "s"}, ":sort -id")    -- a chord → an ex command
vd.unbind("sheet", "t")

vd.bind("sheet", "<F2>", function()            -- a key → your own Lua
  local s = vd.sheet()
  vd.toast(s.column .. " = " .. tostring(s.value))
end, "show cell")

vd.register_renderer {                               -- how cells look
  column = "price",                                  -- or: dtype = "f64"
  render = function(v) return v and string.format("$%.2f", v) end,
}

vd.register_aggregator("range", function(values)     -- for :pivot … range
  local lo, hi = math.huge, -math.huge
  for _, v in pairs(values) do lo = math.min(lo, v); hi = math.max(hi, v) end
  if lo > hi then return nil end                     -- only empty values
  return hi - lo
end)

if vd.api_version < 2 then error("needs a newer vdrs") end  -- 2: functions in vd.bind

vd.bind(layer, keys, action, description?)

layer is "sheet" (normal mode) or "input" (prompts). keys is one key or a table of keys forming a chord, written like "x", "G", "<C-x>", "<A-x>", "<Space>", "<CR>", "<Esc>", "<Tab>", "<BS>", "<Del>", arrows ("<Left>"…), "<Home>", "<End>", "<PgUp>", "<PgDn>", "<F1>". Later bindings win over defaults. action is an action name below, an ex command starting with :, or a Lua function to run when the keys are pressed. An unknown action or invalid command is an error at load time; an error inside a function is shown in the status line.

Action names: cursor_down cursor_up cursor_left cursor_right page_down page_up goto_top goto_bottom goto_leftmost goto_rightmost freeze_column unfreeze_all hide_col unhide_all key_col unkey_all start_rename_col_input type_cast_int type_cast_float type_cast_string type_cast_date type_cast_currency start_search_input start_filter_input start_ex_input search_next search_prev clear_filter clear_sort sort_asc sort_desc open_freq_table open_sheet_switcher submit_row submit_selected toggle_plan_panel pop_sheet quit redraw repeat_last toggle_select_row select_row unselect_row select_all unselect_all start_select_input dup_selected dup_sheet select_equal_cell select_col_duplicates dedupe_rows hide_uniform describe pivot_current start_diff_input undo redo. In the "input" layer only submit_input, cancel_input and input_backspace (or ex commands) do anything.

vd.unbind(layer, keys)

Makes a key do nothing.

vd.command(name, fn)

Adds the ex command :name. fn gets the text after the name ("" without any) and can use vd.sheet(), vd.toast and vd.push_sheet. Names use a-z, 0-9, - and _, and can't be a built-in command or action name. Tab completes them; vd.bind(…, ":name args") binds one to a key once it is defined.

vd.command("hello", function(args) vd.toast("hello " .. args) end)  -- :hello world

vd.register_loader { name?, extensions, open }

Teach vdrs a new file format. open(path) converts the file to one vdrs reads natively (CSV, TSV, Parquet, Arrow, JSON Lines) and returns the path of the result. Used when opening files from the command line and by :diff and :join.

vd.register_loader {
  extensions = { "log" },
  open = function(path)
    local out = os.tmpname() .. ".csv"
    local f = io.open(out, "w")
    f:write("level,message\n")
    for line in io.lines(path) do
      local level, msg = line:match("^(%u+)%s+(.*)$")
      if level then f:write(level, ",\"", msg:gsub('"', '""'), "\"\n") end
    end
    f:close()
    return out
  end,
}

vd.register_aggregator(name, fn)

fn receives the values of one pivot cell as a Lua array and returns a number, a string or nil (an empty cell). Empty values are holes in the array, so loop with pairs: ipairs stops at the first one, and #values is unreliable. Use the name as the last argument of :pivot. It runs in the background, cell by cell; an error stops the pivot and is shown in the status line.

vd.register_renderer { column | dtype, render }

render(value) returns the text to show for cells of that column name, or of that type as shown in the header (i64, f64, str, date, bool, …). Returning nil keeps the normal display. It changes the display only, not sorting, filtering or saved files. Column widths follow the rendered text. Each distinct value is rendered once and remembered, so render should depend only on its argument. Empty cells arrive as nil; if render raises an error, the cell is shown normally.

vd.sheet(), vd.toast(message)

Only inside a function bound with vd.bind. vd.sheet() returns the current sheet: name, cursor.row and cursor.col (counting from 1), column (current column name), value (current cell; nil if empty) and column_names. vd.toast shows a message in the status line.

vd.push_sheet { name, columns, rows }

Only inside a function bound with vd.bind. Opens a new sheet from Lua data once the function returns; q closes it like any other. columns lists the column names in order; rows is an array of rows, each an array of values in that order (nil is an empty cell). name is optional. Each column's type follows its values: all integers → integer, any other number → float, all booleans → boolean, anything else → text.

vd.bind("sheet", "<F3>", function()        -- a sheet listing the columns
  local rows = {}
  for i, name in ipairs(vd.sheet().column_names) do
    rows[#rows + 1] = { i, name, #name }
  end
  vd.push_sheet { name = "columns", columns = { "n", "name", "length" }, rows = rows }
end, "list columns")

A row with more values than columns, a duplicate column name, or a table or function as a value is an error shown in the status line. These sheets can't be exported with :export.

vd.set_theme(name), vd.api_version

"dark" or "light". vd.api_version is a number that grows when the Lua API gains features: 1 is the registration functions above, 2 adds functions in vd.bind, vd.sheet and vd.toast, 3 adds vd.push_sheet, 4 adds vd.command.

Troubleshooting

  • cargo install fails compiling a dependency (for example calamine or zip): add --locked.
  • "no usable terminal (try --headless)": vdrs needs a terminal for the TUI. In scripts or pipes use vdrs --headless file.
  • A column of numbers sorts like text: it was read as text (Excel, SQLite, mixed CSV columns). Press # or %.
  • "no binding: x": that key does nothing in this mode. Press the first key of a chord (g, z) to see what follows.
  • A command prints "working: …" for a while: it is reading the whole file; keep working, the result appears when done.

Limitations

  • Search, select-all and | scan the full data each time; on very large files they take a moment (they run in the background).
  • :join and :sql results are computed once and held in memory, so their row order (and your selections) stay fixed.
  • :export can't rebuild a schema diff (D with no key columns), pivots with a Lua aggregator, or stdin. SQL scripts load DuckDB's excel / nanoarrow extensions for Excel / Arrow files; nanoarrow can't read Arrow files with string-view columns (as Polars writes them). Joins and diffs may come out in a different row order, DuckDB pivots show 0 where vdrs shows empty, and :sql queries run as written by the other engine.
  • Deliberately left out: Python expressions, VisiData's options system, clipboard, macros and interactive cell editing (see docs/direction.md in the repository).
