visidata-rs · user guide

Explore tables in your terminal.

vdrs (visidata-rs) is a modal terminal data explorer. It reads CSV, Parquet, JSON, Excel and SQLite through Polars, shows them in a keyboard-driven table, and lets you sort, filter, pivot, join and query without leaving the terminal. If you know VisiData, most keys will feel familiar.

  • Any tableCSV, Parquet, JSON, Excel and SQLite, read lazily: big files open at once.
  • Keyboard firstSort, filter, select and drill down with VisiData's keys.
  • Pivot, join, diffReshape and combine files without writing code.
  • SQL when you want it:derive and :sql take SQL expressions and queries.
  • Reproducible:export writes the view as a Polars or DuckDB script.
  • ScriptableBind keys and add commands, loaders and aggregators in Lua.

Install

You need a Rust toolchain (1.88 or newer):

cargo install --git https://github.com/neumann-mlucas/visidata-rs --locked

This installs the vdrs binary. --locked builds with the dependency versions the project is tested with; without it Cargo may pick newer, incompatible releases.

Opening data

vdrs sales.parquet                 # open in the TUI
vdrs data/                         # every *.parquet file in a directory, as one table
cat events.jsonl | vdrs -          # read stdin; format is sniffed
vdrs --format tsv export.txt       # force a format when the extension is wrong
vdrs --headless --head 20 big.csv  # print schema and the first 20 rows, no TUI
FormatExtensionsNotes
CSV / TSV.csv, .tsv, .tabFirst row is the header. ISO dates load as dates; other layouts (7/3/2018 is ambiguous) stay text until @. Column types come from the whole file (first 100,000 rows above 256 MB). Rows with too few fields are padded, extra fields dropped; invalid UTF-8 is replaced.
Parquet.parquet, .pq, a directoryA directory means all its *.parquet files.
Arrow IPC.arrow, .ipc, .feather
JSON Lines.jsonl, .ndjsonOne record per line.
JSON.jsonAn array of records. A .json file that is really JSON Lines is detected.
Excel / ODS.xlsx, .xls, .xlsm, .xlsb, .odsA column whose cells are all numbers, all true/false or all dates loads with that type; a mixed column loads as text (the type keys convert it). Several worksheets → a list to pick from; book.xlsx:Sheet2 opens one directly (also in :join/:diff).
SQLite.sqlite, .sqlite3, .dbA column holding only integers loads as integers, only numbers as floats; anything else as text, nothing lost. Several tables → a list to pick from; app.db:users opens one directly.
DuckDB.duckdb, .ddbNeeds the duckdb program on PATH (or vd.option("duckdb_cmd", …)). Opens a list of tables and views with their schema, row and column counts, as VisiData; Enter opens one, typed. app.duckdb:main.users opens one directly. :exec-sql runs SQL in the file; :save x.duckdb writes a table.
gzipany of the above + .gzThe inner extension (or --format) decides the format.

Files are scanned lazily: vdrs only loads a 1024-row window around the cursor and counts rows in the background, so large files open immediately. Other formats can be added with a Lua loader.

A first session

vdrs sales.csv (the file is in docs/fixtures) opens the table at once; the row count in the title bar shows ? until it has been counted. Step through the recording with the buttons or ← →; under each caption are the keys typed.

From here:

  • On region, z| ^n Enter keeps the regions starting with n (Search, sort, filter).
  • While you type :pivot region date total, the right half of the screen says what comes next and previews the result (Sheets).
  • U undoes a step. :save north.parquet writes the view; :export north.py writes a Python script that rebuilds it from sales.csv.

Nothing you do changes sales.csv.

  • Title bar: the sheet name; chips for what shapes the view (a spinner while work runs, source format, open sheets, filter, sort with ▲/▼, sel count, hidden columns); then the current column with its position, and row N/total · % (? while rows are still being counted). Long names are shortened from the left so the position stays visible.
  • Header: column names with a dim type badge (i integer, f float, str text, date, …). On a sorted column the badge becomes ▲ or ▼, followed by its rank when sorting by several columns (▼2). Numbers and their headers sit on the right.
  • Status line: a short key hint, or messages, prompts (/, :, …), working: … while a long command runs in the background, a pending count (count: 3) or a pending key chord. When you press the first key of a chord (for example g or z), a popup lists what can follow.

Messages stay until your next key press.

Workflows

Real tasks, start to finish. Every screen here is recorded from vdrs by the test suite, so it is exactly what you will see. The files are in docs/fixtures: cd docs/fixtures and follow along.

Clean up a messy export

A billing system exported orders_raw.csv with US dates, formatted amounts, and some orders twice. Make it a typed table with one row per order.

Then :save orders.parquet writes the clean sheet with real date and float types, and :export clean.py writes a Polars script that repeats the steps on next month's export.

Triage errors in a log

app.jsonl holds a morning of application events. Find where the errors come from, by drilling down through frequency tables.

Each Enter on a frequency row opens a new sheet and q walks back; S lists the open sheets. For a log that is still being written, :tail app.jsonl -f keeps the sheet up to date.

Build a monthly report

Revenue per month and region from sales.csv: two derived columns, a pivot, and one SQL query.

:derive takes SQL expressions (here strftime); :sql runs a whole query on the current sheet, called self. On the pivot, :save report.csv writes the table for a spreadsheet.

Compare two exports

What changed between last week's price list and this week's? Match the rows by sku.

only_a rows are only in the open file, only_b only in the other, and changed rows are in both with different values; the other file's values are in the _right columns. With key columns set (!), D asks for the file and uses them.

Enrich with a lookup table

Orders know only a customer_id. Join customers.csv to break revenue down by customer segment.

A left join keeps every order, also those without a matching customer. The other side can be any file vdrs reads, an open sheet's name, or #2 (a sheet id from S).

Sheets

Many commands open a new sheet on top of the current one. q closes the top sheet (and quits on the last one); S lists open sheets (Enter jumps to one). New sheets are built from what you see: the current filter, sort, types and visible columns.

Keys / commandOpens
FFrequency table of the current column: each value with count, percent and a histogram bar, most common first (number and date columns keep first-seen order, as in VisiData). On it, Enter opens the original rows with that value; select several values and press gEnter to open the rows of all of them.
IDescribe, as VisiData: one row per column with errors (values a type cast failed on), nulls, distinct (null counts as one value), mode (most common; the first seen on a tie), and for numbers min, max, sum, median, mean, stdev. Dates get min, max and, when their count is odd, the middle median. The sheet and type columns are hidden; gv shows them.
WPivot: one row per key-column combination, one column per value of the current column, counts in the cells. With no key columns: a single row of counts.
:pivot index on values [agg]Pivot with an aggregate: sum (default), mean, count, min, max, first, last, or a Lua aggregator. While you type it, a panel on the right says which argument comes next, lists the columns, and then previews the pivot of the first 10,000 rows; Enter pivots everything.
:unpivot a,b -- idLong format: columns a, b become variable/value rows, keeping id.
:join other.csv id [type]Join with a file, an open sheet's name, or #2 (sheet id from S) on columns with the same name. Types: inner (default), left, full, merge (full join; the other side's non-empty values win), append (stack rows, columns matched by name), concat (stack rows, columns matched by position, named after the current sheet's). Both need no key and add a hidden origin_sheet column naming each row's sheet; g- shows it.
D or :diff file [keys]Compare with another file. With key columns (D uses yours): the rows that differ, tagged only_a, only_b or changed. Without keys: a column-by-column schema comparison.
:sql SELECT … FROM selfRun SQL (Polars SQL) on the current sheet, called self. Other open sheets are s0, s1, … (ids from S).
:exec-sql CREATE …; SELECT …On a .duckdb file's list or one of its tables: run statements in that file through the duckdb program, read-write. If the last statement is a query its rows open as a sheet; the table list reloads either way.
g" or :dupA copy of the current sheet.
y, gyCopy the current row / the selected rows (in view order, every column, hidden ones too) to vdrs's clipboard. It stays across sheets; p pastes them.
zy, gzyCopy the current cell / the current column of the selected rows.
zp, gzpPaste copied cells: into the current cell (the first one) / into the current column of the selected rows, in view order, repeating them to fill. Every value must fit the column, or nothing changes.
zx, gzxCut: copy the current cell / the current column of the selected rows, then empty them.
zd, gzdEmpty the current cell / the current column of the selected rows, without copying.
Paste with the terminal (CtrlShiftV, middle click)Pasted text becomes vdrs's clipboard: tab-separated lines (comma-separated when there is no tab), by position from the first column, or by name when the first line holds column names (as Y copies them). One column fills zp; more fill p. In a prompt it types the first line.
zP, gzPPaste the system clipboard into cells, as VisiData: tab-separated lines from the current cell down and rightwards / into the selected rows, from the current column. Lines past the last row add rows. An empty field empties the cell (text columns get empty text). The clipboard comes from clipboard_paste_cmd; over SSH, from your last terminal paste.

Commands that read the whole data (search, select all, |, z|, ,, ", I, W, :pivot, :save) run in the background; the status line shows working: … and you can keep moving. Ctrl-c drops the current sheet's background work, gCtrl-c all of it.

Changing data

vdrs never modifies your files; changes live in the sheet until you :save. Closing a sheet with unsaved edits (q, gq, :q) asks discard 2 edits to sales.csv? y/N; :q! and :qa! don't ask. Only sheets read from a file take edits; frequency tables, pivots, joins, :sql results and other derived sheets are read-only (copying still works).

CommandAction
=, :derive total = qty * priceAdd a computed column. = asks for the expression and names the column after it (qty * price); total = qty * price names it total unless total already exists, in which case the whole text is the expression. The expression is SQL (CASE WHEN …, upper(name), price * 1.2, …).
e, :edit valueEdit the current cell; e starts from its value. The value must fit the column as shown (after # % @ …) and its type in the file; empty sets it to null. Columns computed from it (:derive) follow the edit; editing a computed cell pins it.
ge, :setcol 0Set the current column to a value on the selected rows, with the same type rules.
g=, :setexpr qty * priceSet the current column on the selected rows to a SQL expression of each row, as VisiData's setcol-expr. It reads the columns as the file has them (like :derive), not the type keys' casts; its result must fit the column's type (any value fits a text column). Undo, :save and :export treat it as an edit.
a, gaAdd a blank row after the current row / ask how many; the cursor moves to the first one. Added rows keep their place: sort, then clear the sort (zo), and they're back where you put them.
p, PPaste the copied rows (y, gy) after / before the current row. Columns match by name; ones the rows lack stay empty, ones the sheet lacks are added; a value that doesn't fit its column refuses the paste.
AA new empty sheet with one column, A, to type into; :save writes it.
d, gdDelete the current row / the selected rows. The next row moves up under the cursor.
x, gxCut: copy the current row / the selected rows (as y), then delete them.
:uniformHide columns that hold a single value.
U, RUndo, redo. Covers column changes, types, sorting, filtering, selection, :derive, edits, :setcol, pastes and deleted rows, which come back in place. A change after U starts a branch instead of losing what was undone: R follows the branch you last came from, :earlier / :later and :undotree reach the others (100 states per sheet; old branches go first).

Saving & export

CommandAction
:save out.parquet (:w)Write every row of the current view (filter, sort, types, visible columns). The extension picks the format: .csv, .tsv, .parquet, .arrow/.ipc, .jsonl, .json; .duckdb/.ddb writes a table named after the sheet (data.csv → data), replacing one of that name and keeping the file's other tables. An existing file is overwritten; an unknown extension is refused and leaves the file alone.
:export view.py, :export view.sqlWrite a script that rebuilds the current view from the source files: Python with Polars, or SQL for DuckDB. Derived sheets (frequency, copy, selected rows, :join, :sql, :pivot, W, :unpivot, describe, row diff) are rebuilt step by step from the sheet they came from, as it was when you made them.

For example, filtering region on ^n, pressing F on qty and running :export qty.py writes:

import polars as pl

t1 = pl.scan_csv("sales.csv")
t2 = t1.filter(pl.col("region").cast(pl.Utf8).str.contains("^n"))
t3 = t2.group_by("qty").agg(pl.len().alias("count")).with_columns(…).sort(["count", "qty"], …)

print(t3.collect())

Each sheet becomes one variable (t1, t2, …); in .sql each is a WITH table. Run it with python qty.py or duckdb -c ".read qty.sql". See Limitations for what can't be exported.

Following files

:tail app.jsonl -f opens a file that keeps growing and checks it every 2 seconds. With -f (follow), if you are on the last row you stay on the last row as new rows arrive. For CSV, TSV and JSON Lines only the new lines are read. :tail data/ -f on a directory picks up new Parquet files.

Sidebar & plan

b opens a sidebar on the right; Ctrl-g moves through its pages: column (the cursor column's row of I: type, errors, nulls, distinct, mode, min, max, sum, median, mean, stdev, worked out in the background), cell (the cursor cell's whole value, wrapped), help (the key bindings) and plan. :sidebar column (or cell, help, plan, plan-opt) opens a page directly. :plan shows the Polars query behind the current window; again for the optimized plan, a third time to close. Prompt editing

All prompts (/, :, =, filters, rename, diff) support: ← →, Home/Ctrl-a, End/Ctrl-e, Backspace, Del, Ctrl-u (delete to start), Ctrl-w (delete previous word). Enter runs, Esc cancels. In the : prompt, ↑/↓ walk the command history (kept in $XDG_STATE_HOME/vdrs/exline_history), and Tab completes the command name: one match is filled in, several are listed after the prompt and filled in up to where they differ.

Arguments are split on spaces; use quotes ("a b" or 'a b') or a backslash for spaces inside one argument.

Lua configuration

vdrs runs $XDG_CONFIG_HOME/vdrs/init.lua (usually ~/.config/vdrs/init.lua) at startup. The first time the TUI starts without one, vdrs writes it with every default binding listed but commented out: uncomment a line to change it. Defaults you leave commented keep following new releases. Saving the file while vdrs runs reloads it within about two seconds. If it has an error, everything registered before the error still applies and the error is shown in the status line.

-- ~/.config/vdrs/init.lua
vd.set_theme("light")                               -- "dark" (default) or "light"
vd.option("clipboard_copy_cmd", "wl-copy")          -- what Y / gY / zY / gzY pipe to
vd.option("clipboard_paste_cmd", "wl-paste")        -- what zP / gzP read
vd.option("duckdb_cmd", "/opt/duckdb/bin/duckdb")    -- the program .duckdb files go through

vd.bind("sheet", "x", "goto_bottom", "jump to end") -- a key → an action
vd.bind("sheet", {"<Space>", "s"}, ":sort -id")    -- a chord → an ex command
vd.unbind("sheet", "t")

vd.bind("sheet", "<F2>", function()            -- a key → your own Lua
  local s = vd.sheet()
  vd.toast(s.column .. " = " .. tostring(s.value))
end, "show cell")

vd.register_renderer {                               -- how cells look
  column = "price",                                  -- or: dtype = "f64"
  render = function(v) return v and string.format("$%.2f", v) end,
}

vd.register_aggregator("range", function(values)     -- for :pivot … range
  local lo, hi = math.huge, -math.huge
  for _, v in pairs(values) do lo = math.min(lo, v); hi = math.max(hi, v) end
  if lo > hi then return nil end                     -- only empty values
  return hi - lo
end)

if vd.api_version < 2 then error("needs a newer vdrs") end  -- 2: functions in vd.bind

vd.bind(layer, keys, action, description?)

layer is "sheet" (normal mode) or "input" (prompts). keys is one key or a table of keys forming a chord, written like "x", "G", "<C-x>", "<A-x>", "<Space>", "<CR>", "<Esc>", "<Tab>", "<BS>", "<Del>", arrows ("<Left>"…), "<Home>", "<End>", "<PgUp>", "<PgDn>", "<F1>". Later bindings win over defaults. action is an action name below, an ex command starting with :, or a Lua function to run when the keys are pressed. An unknown action or invalid command is an error at load time; an error inside a function is shown in the status line.

In the "input" layer only submit_input, cancel_input and input_backspace (or ex commands) do anything.

vd.unbind(layer, keys)

Makes a key do nothing.

vd.command(name, fn)

Adds the ex command :name. fn gets the text after the name ("" without any) and can use vd.sheet(), vd.toast and vd.push_sheet. Names use a-z, 0-9, - and _, and can't be a built-in command or action name. Tab completes them; vd.bind(…, ":name args") binds one to a key once it is defined.

vd.command("hello", function(args) vd.toast("hello " .. args) end)  -- :hello world

vd.register_loader { name?, extensions, open }

Teach vdrs a new file format. open(path) converts the file to one vdrs reads natively (CSV, TSV, Parquet, Arrow, JSON Lines) and returns the path of the result. Used when opening files from the command line and by :diff and :join.

vd.register_loader {
  extensions = { "log" },
  open = function(path)
    local out = os.tmpname() .. ".csv"
    local f = io.open(out, "w")
    f:write("level,message\n")
    for line in io.lines(path) do
      local level, msg = line:match("^(%u+)%s+(.*)$")
      if level then f:write(level, ",\"", msg:gsub('"', '""'), "\"\n") end
    end
    f:close()
    return out
  end,
}

vd.register_aggregator(name, fn)

fn receives the values of one pivot cell as a Lua array and returns a number, a string or nil (an empty cell). Empty values are holes in the array, so loop with pairs: ipairs stops at the first one, and #values is unreliable. Use the name as the last argument of :pivot. It runs in the background, cell by cell; an error stops the pivot and is shown in the status line.

vd.register_renderer { column | dtype, render }

render(value) returns the text to show for cells of that column name, or of that type as shown in the header (i64, f64, str, date, bool, …). Returning nil keeps the normal display. It changes the display only, not sorting, filtering or saved files. Column widths follow the rendered text. Each distinct value is rendered once and remembered, so render should depend only on its argument. Empty cells arrive as nil; if render raises an error, the cell is shown normally.

vd.sheet(), vd.toast(message)

Only inside a function bound with vd.bind. vd.sheet() returns the current sheet: name, cursor.row and cursor.col (counting from 1), column (current column name), value (current cell; nil if empty) and column_names. vd.toast shows a message in the status line.

vd.push_sheet { name, columns, rows }

Only inside a function bound with vd.bind. Opens a new sheet from Lua data once the function returns; q closes it like any other. columns lists the column names in order; rows is an array of rows, each an array of values in that order (nil is an empty cell). name is optional. Each column's type follows its values: all integers → integer, any other number → float, all booleans → boolean, anything else → text.

vd.bind("sheet", "<F3>", function()        -- a sheet listing the columns
  local rows = {}
  for i, name in ipairs(vd.sheet().column_names) do
    rows[#rows + 1] = { i, name, #name }
  end
  vd.push_sheet { name = "columns", columns = { "n", "name", "length" }, rows = rows }
end, "list columns")

A row with more values than columns, a duplicate column name, or a table or function as a value is an error shown in the status line. These sheets can't be exported with :export.

vd.option(name, value)

Sets an option; an unknown name is an error. clipboard_copy_cmd: the command Y and friends pipe text to, split on spaces, or "osc52" to send it through the terminal (works over SSH and in tmux with set-clipboard on). Default, as VisiData: osc52 when $SSH_TTY is set, else clip.exe on Windows/WSL, pbcopy on macOS, wl-copy under Wayland, xclip -selection clipboard -filter otherwise. Tabs and newlines inside values are copied as U+001F and U+001E, as VisiData does. clipboard_paste_cmd: the command zP and gzP read the clipboard from (its output). Default, as VisiData: powershell.exe -noprofile -command Get-Clipboard on Windows/WSL, pbpaste on macOS, wl-paste under Wayland, xclip -selection clipboard -o otherwise; none over SSH, where they paste your last terminal paste. duckdb_cmd: the DuckDB program .duckdb files, :exec-sql and :save x.duckdb run (default duckdb on PATH); vdrs links no DuckDB library.

vd.set_theme(name), vd.api_version

"dark" or "light". vd.api_version is a number that grows when the Lua API gains features: 1 is the registration functions above, 2 adds functions in vd.bind, vd.sheet and vd.toast, 3 adds vd.push_sheet, 4 adds vd.command, 5 adds vd.option, 6 its duckdb_cmd, 7 its clipboard_paste_cmd.

Troubleshooting

  • cargo install fails compiling a dependency (for example calamine or zip): add --locked.
  • "no usable terminal (try --headless)": vdrs needs a terminal for the TUI. In scripts or pipes use vdrs --headless file.
  • A column of numbers sorts like text: it was read as text (a mixed Excel or SQLite column, a mixed CSV column, or whole numbers with a leading zero). Press # or %.
  • "no binding: x": that key does nothing in this mode. Press the first key of a chord (g, z) to see what follows.
  • A command prints "working: …" for a while: it is reading the whole file; keep working, the result appears when done.

Limitations

  • Search, select-all and | scan the full data each time; on very large files they take a moment (they run in the background).
  • :join and :sql results are computed once and held in memory, so their row order (and your selections) stay fixed. A join lists rows as VisiData does: keys in the order first seen (this sheet, then keys only the other has), each key's rows together.
  • A CSV column of whole numbers stays text when a value starts with a zero (082053, zip codes, ids), so no digit is lost; # makes it a number.
  • :export can't rebuild a schema diff (D with no key columns), pivots with a Lua aggregator, or stdin. SQL scripts load DuckDB's excel / nanoarrow extensions for Excel / Arrow files; nanoarrow can't read Arrow files with string-view columns (as Polars writes them). Diffs may come out in a different row order, DuckDB pivots show 0 where vdrs shows empty, and :sql queries run as written by the other engine.
  • Deliberately left out: Python expressions, VisiData's options system, clipboard, macros and interactive cell editing (see docs/direction.md in the repository).
